# 점검 결과 — 2026-11-26 (Windows + WSL2)

환경: Windows 11, WSL2 Ubuntu, herdr-core(`hc`) 0.1.22, herdr-app, Claude Code 2.1.332, OpenRig 0.7.23.
WSL 안 Claude Code 세션에서 점검 에이전트 3개를 `hc run`으로 띄워 영역을 나눠 시험했습니다.
테스트 터미널은 모두 지웠고 서버 재시작과 설정 변경은 하지 않았습니다.

## 이 저장소에 반영한 것

| 문제 | 원인 | 조치 |
|---|---|---|
| 보드의 OpenRig 팀 목록(`rig ps`)이 실패하고 `hc run claude`가 `cannot start "claude"`로 끝남 | herdr-core가 systemd 사용자 서비스(`hc-serve-*`)로 돌아서 `~/.profile`을 읽지 않고, PATH에 `~/.local/bin`이 없음. `hc exec sh -c 'command -v rig'`로 확인하면 찾지 못함 | `setup-wsl.sh`가 `claude`·`rig`·`hc`·`herdr-core`를 `/usr/local/bin`에 링크. README에 이미 설치한 경우의 한 줄 명령을 적음 |
| Agent(Task) 도구로 띄운 서브에이전트가 보드에 안 보임 | 같은 Claude Code 프로세스 안에서 돌아서 Herdr 터미널이 아님 | README에 `hc run --bg claude …`로 띄우는 방법을 적음 |

## herdr-core 0.1.22에서 발견한 이상 (업스트림, 이 저장소와 무관)

| 명령 | 현상 |
|---|---|
| `hc run --rm …` | 포그라운드 출력이 나오지 않음. 드물게 종료코드도 사라짐(`[hc] tX ended`, rc 1) |
| `hc run --json …`, `hc exec --json …` | 프로그램이 exit 3이어도 hc는 rc 0을 반환하고, 코드는 JSON 안에만 있음 |
| `hc run` 포그라운드 | `[hc] tX exited (exit N)` 상태 줄이 stdout으로 나와 파이프 출력에 섞임 |
| `hc wait <t>`, 일반 셸·REPL | 프롬프트에서 쉬고 있어도 idle로 감지하지 못하고 timeout으로 끝남. timeout이어도 rc 0 |
| `hc wait --output X` | wait를 시작한 뒤에 찍힌 출력만 찾음. `send` 직후 바로 끝난 출력은 놓침(help에 적힌 동작) |
| `hc keep --help` | `--off` 설명이 반대 의미임. 실제 동작은 정상 |
| `hc keys … Z` | 대문자가 소문자로 입력됨. `shift+z`는 정상 |
| `hc --help`의 `wait --children` | 값을 반드시 줘야 함(`any` 또는 `all`) |
| `echo req \| hc connect` | stdin이 EOF가 되면 오래 걸리는 요청(`machine.exec` 등)의 응답이 사라짐 |
| `hc schema \| head` | broken pipe에서 panic 발생 |
| `hc exec` | 출력이 8MB에서 잘리지만 rc는 0이고, 상한이 문서에 없음 |
| `hc ls`와 `hc get` | `agent` 값이 다름. ls는 `claude-code`, get은 `null`이고 값이 `status.app`에만 있음 |

이 밖에 exec의 stdout/stderr 분리·종료코드·stdin·한글·5MB 출력, `file read/write/edit`, `put`, `events`, `schema`,
`templates`, `machine ls`, 없는 머신 `--on` 에러, 이름 지정, `send`, `keys`, `interrupt`, `kill`, `rm`, 시그널로 죽었을 때 `keep`이 셸로 복구하는 동작은 모두 PASS였습니다.
